
I need a Python developer to extract structured transaction data from approximately **4,200 exported Outlook emails** and place the results into Excel and CSV files.

The emails cover approximately 15 years of transaction approvals. They have already been exported from Outlook, so **no mailbox access, Microsoft account access, or Microsoft Graph work is required**.

The export includes:

* Original `.eml` files
* A `messages.jsonl` file containing email metadata and email bodies
* A `messages_index.csv` file containing an index of the exported messages

There are **no PDFs, scanned documents, or attachments to process**. All relevant data is contained in the email bodies.

I also have an existing Excel workbook covering approximately the most recent 18 months. This workbook will serve as the known-good reference for understanding the output structure and validating the accuracy of the extraction.

## Nature of the Emails

The emails are semi-structured but largely standardized.

My current estimate is:

* Approximately 90% of the emails follow five or six common formats
* There may be approximately 15 format variations in total
* At least 95% of the emails should be capable of automated extraction
* I am prepared to handle the remaining exceptions manually

The goal is not to create a system that interprets every unusual email. The goal is to build a dependable parser for the standardized majority and produce a clear exception report for anything that cannot be processed confidently.

## Primary Objective

Develop a reliable and repeatable Python program that:

1. Reads the exported email data
2. Recognizes the applicable email format
3. Extracts each individual transaction
4. Produces structured transaction-level data
5. Aggregates the data into the format used by my existing Excel workbook
6. Identifies and reports exceptions without guessing
7. Allows every output record to be traced back to its source email

The preferred approach is deterministic and rule-based, using:

* Python
* Standard email and MIME parsing libraries
* Regular expressions
* Format-specific parsing templates
* pandas
* OpenPyXL or XlsxWriter

AI or external language-model services should not be necessary for the standardized formats. Confidential email content may not be sent to an external AI service without my prior written approval.

One email may therefore need to produce multiple transaction-level rows.

## Required Processing Logic

The program should:

1. Read the `.eml` files or the `messages.jsonl` file.

2. Identify which recognized format or template applies to each email.

3. Extract all transactions from the relevant email content.

4. Avoid accidentally parsing:

* Quoted email history
* Forwarded material that is not part of the approval
* Email signatures
* Confidentiality notices
* Standard disclaimers
* Unrelated text

5. Correctly handle emails containing multiple transactions.

6. Convert amounts into proper numeric fields, including values containing:

* Dollar signs
* Commas
* Percentages
* Decimals
* Parentheses
* Other common financial formatting

7. Standardize issuer names according to the existing workbook.

8. Apply block and equity classifications consistently with the reference workbook.

9. Aggregate transaction-level records into the required summary rows.

10. Detect duplicate emails using message identifiers and, where useful, content hashes.

11. Perform mathematical checks when the email provides par amount, price, and market value.

12. Flag missing, inconsistent, or ambiguous data rather than inventing a value.

13. Continue processing when an individual email cannot be parsed.

14. Produce a complete exception report.

15. Produce a processing log showing:

* Successfully processed emails
* Duplicate emails
* Skipped emails
* Exception emails
* Failed emails

## Exception Handling

I am prepared to review and manually handle the unusual emails that fall outside the standardized formats.

The exception report should make that review straightforward. For each exception, it should include:

* Source `.eml` filename
* Source-folder path
* Email subject
* Email date
* Source message ID
* Suspected format
* Fields successfully extracted
* Missing or ambiguous fields
* Clear reason the email was classified as an exception
* Suggested action, when obvious

The parser must not silently omit an email or transaction. Every source email should end with a clearly documented status, such as:

* Successfully parsed
* Duplicate
* Excluded under an agreed rule
* Needs manual review
* Failed due to a technical error
